# Pause screen, narration log, save/continue

Goal (user): "add a pause screen as well and save/continue functionality. pause screen should also allow going through all the narration spoken."

## As built

- **Narration log**: `Narrator.play()` appends every line that actually plays to `GameState.narration_log` (`{cue, text, audio}`; text = the full subtitle with `|`/newlines flattened, also for `show_subtitle = false` cues such as `quiz_question`). Capped at 1000 entries; saved with the game.
- **Pause menu** (`core/pause/pause_menu.gd`, autoload `PauseMenu`, CanvasLayer 110, Process Always, UI built in code with `menus/menu_theme.tres`): darkened game + Ben-Day dots, red "PAUSED!" title, caption box, buttons RESUME / NARRATION LOG / SAVE GAME / QUIT TO TITLE / QUIT GAME (hidden on web). Opening sets `get_tree().paused = true` and `Narrator.set_paused(true)` (new: holds the voice, the reading timer and the chunk timer, hides the subtitle; carries on after). Music/SFX play on (Audio is Process Always). Narration log: paper panel with every line, newest at the bottom (scrolled there on open); ▶ replays a voiced line on its own player (■ / second press stops), "…" for subtitle-only lines. Opens only in game scenes (`SaveGame.in_game()`: scene path under `res://world/` or `res://minigames/`) and never during a Transition fade.
- **Key rule** (least disruptive): **Esc keeps every meaning a screen already gives it; P always pauses.**
  - Esc opens the pause menu where it meant nothing else: walking around the office (it used to only free the mouse; `Player` now calls `PauseMenu.open()`, Resume recaptures the mouse, click-to-recapture still works) and the computer screen (caught in `_input` before minigames swallow keys; except while the antivirus pop-up is up, whose gag is a refused Esc-close).
  - P opens it in the office and every close-up/in-world switch game (screwdriver, wires, valve, candle, gargoyle quiz, scope view, placeholder), where Esc still walks away/leaves. At the computer and on the kaleidoscope keypad P is a typed letter and stays one.
  - While open: Esc or P resumes; Esc in the log goes back to the menu.
  - Auto-pause on focus loss: skipped.
- **SaveGame** (`core/save/save_game.gd`, autoload `SaveGame`), file `user://save.json` (IndexedDB on web), written with `JSON.from_native` so Transform3D/StringName/typed containers survive. Holds every GameState script variable (`GameState.to_save()`, all except `computer_return_scene`): story step, switch_progress, power_on, unlocks, computer_queue (+ exit flag), minigames_completed, bank_balance, score, ads_closed, password, document font, idle counters, chair_push_time, stray_touches, kaleidoscope fields, player_poses, narration_log; plus `Narrator.played_cues()` (`once` lines) and the scene to resume in. Derived on load by `Story.restore()`: room swap, ESDF shift (the shift's explanation still plays if it never did), computer/switchboard unlocks; a dark switch step replays its blackout directions on arrival (unless `once` and played).
  - API: `SaveGame.has_save() -> bool`, `SaveGame.continue_game() -> bool` (loads, then `Transition.change_scene` to the office, or the computer if saved there mid-visit with minigames left; that visit resumes at the unbeaten minigame), `SaveGame.new_game()` (Narrator stop, `GameState.reset()`, played cues cleared, `Story.restart()`, save deleted, then the normal new-game flow: `menus/character_select/character_select.tscn`), plus `save()`, `autosave()`, `delete_save()`, `in_game()`, signal `saved`.
  - Autosave (only while in a game scene, never on the title screens): every story step change, beaten switch game, beaten computer minigame, power change, Save/Quit to title/Quit in the pause menu, and the window close request. Before saving it stores the player's current office pose (`Player.remember_pose()`, skipped while frozen/locked, e.g. on the quiz hot seat).
- New helpers: `GameState.reset()` / `to_save()` / `from_save()` / `log_narration()` (defaults snapshotted in `_ready`, typed containers filled in place); `Story.restart()` / `Story.restore()`; `Narrator.set_paused()` / `played_cues()` / `set_played_cues()`; `Transition.is_busy()`.
- `project.godot`: two autoload lines (`SaveGame`, `PauseMenu`, after `Story`). Start menu untouched (another agent wires CONT. LAST GAME / NEW GAME to `continue_game()` / `new_game()`).
- Verified with a temporary windowed driver (deleted): Esc pauses on the computer (memo_mail visit) and resumes; F7 to SWITCH_3; a `quiz_question` cue logged with its text; Esc pauses in the office, tree paused, narrator held; log lists every line, ▶ replay plays; Esc in log → menu; resume unpauses, mouse captured again; P pauses/resumes in the office; P types on the keypad and Esc still leaves it; P pauses the candle close-up and Esc still leaves it; Save button bursts "SAVED!"; Quit to title → start menu with a save; after scrambling state `continue_game()` restores step, power, swap, unlocks, switch progress, bank, minigames, played cues, ESDF shift, log and the (moved) player pose; `new_game()` resets everything, deletes the save and opens character select. 0 failures, no errors/warnings in the run logs (only the known exit leak).
- Limitations: on the web, browsers eat the first Esc to exit pointer lock (the mouse is freed, no pause): press P or Esc again. Minigame timers based on wall-clock time (`Time.get_ticks_msec`) see the paused time pass. A save made inside the gargoyle quiz/scope resumes in the office at the last free-walking pose with the quiz/scope closed.
